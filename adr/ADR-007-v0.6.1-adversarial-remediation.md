# ADR-007 — Motus 0.6.1 adversarial remediation

- **Status:** PROPOSED
- **Date:** 2026-08-04
- **Authority:** founder directive to remediate the independent 0.6 audit
- **Depends on:** ADR-001, ADR-005, ADR-006
- **Audit evidence:** `audit/0.6-adversarial-opus` at `3728fcb`

## Context

The independent Motus 0.6 audit at release-main SHA `2a860a7` resisted 80
distinct attacks but returned FAIL on three release-blocking defects:

1. an evidence-free native `Rejection` lost its private absence sentinel
   through `deepcopy`, so a logically successful run could carry a non-JSON
   object and become impossible to persist or validate;
2. `max_transitions` counted only committed writes, so an EXPLORATION cycle
   whose nodes kept raising could produce an unbounded trace without a terminal
   record;
3. the published trace-preparation ratio timed `to_dict()` after `to_json()`
   had been memoized, measuring a cached parse rather than cold document
   materialization.

The audit also identified five bounded MEDIUM/LOW defects: keyed state reads
scanned the append-only log, defaulted node parameters were mistaken for
RunContext, callable configuration identity was stale across reused Runtime
instances, a supplied sink was ignored under the in-memory profile, and a
pre-run cancellation was discarded. It also disproved an absolute Listener
claim that no arbitrary synchronous callback can affect execution.

## Decision

### 1. Optional rejection evidence remains absent across copies

The private missing-value sentinel is identity-stable under shallow and deep
copy. `Rejection(what, reason, ts)` omits `evidence` from every state and trace
wire form. Supplying evidence still requires a strict RFC 8259 JSON value.
A successful run must never carry a value that its trace cannot serialize.

### 2. `max_transitions` bounds routing-producing activations

The name stays stable for GraphSpec compatibility. Its normative unit is now a
**routing-producing node activation**, not a committed state mutation:

- `transition(returned, commit)` counts once;
- `transition(raised, continue)` counts once;
- `transition(raised, retry)` does not count because the activation has not yet
  traversed a graph edge;
- abort and cancellation terminate independently and need no cycle bound.

After the counted transition's routing record, reaching the declared limit
ends the run as `run_failed(transition_limit_exceeded)` before the selected
node begins. E11 validates that the trace contains exactly that many
routing-producing activations. This is a clarification and correction of R11,
whose purpose was always to bound cyclic execution even when nodes fail.

### 3. Cold materialization and cached encoding are named separately

`Trace.to_dict()` always performs fresh document materialization and returns an
isolated strict-JSON object. `Trace.to_json()` may continue to memoize its
immutable encoding. Benchmarks must therefore distinguish:

- cold `to_dict()` materialization;
- cached `to_json()` retrieval, when measured as a separate convenience path;
- pure `json.dumps(document)` as the reference encoder.

ADR-006's `0.788x` figure is retained as historical evidence of the invalid
method, not repeated as a product claim. A new five-run Python 3.10.12 / AMD
EPYC characterization is required for 0.6.1. The corrected cold ratio is
published honestly even if it is measured debt; the CI gate must bind to that
new raw evidence rather than the 0.6.0 cache-hit profile.

### 4. Pre-run cancellation is consumed once

`Runtime.cancel(reason)` called while idle queues one cancellation for the next
run. The run emits `run_started`, then `run_cancelled`, executes no node, and
consumes the request. A later run is not cancelled unless another request is
made. Cancellation during an active run retains the existing checkpoint
semantics.

### 5. Keyed state reads use a persistent immutable index

Facts and decisions in completed append-log chunks are indexed by
`(collection, key)`. The current partial chunk is scanned directly, so a keyed
lookup examines at most 63 log entries before one dictionary access. The
index is copied only when a 64-item chunk closes; old State snapshots retain
their exact prior view. Scans and snapshots keep append order and origins.

### 6. Node binding and identity describe the invocation that occurred

A second positional node parameter receives RunContext only when it is
required. A defaulted second parameter is left at its Python default. Callable
configuration material and replay constraints are refreshed at each run
start; unchanged rows reuse their digest, while changed `motus_config()`
material recomputes the code fingerprint. Reusing a Runtime therefore cannot
attest stale code identity or pay repeated hashing for unchanged config.

### 7. An attached sink is never silently discarded

If a sink is supplied under the in-memory profile, Motus opens it and forwards
records synchronously. The profile still promises no crash durability; it is
a lower-bound guarantee, not permission to discard an explicitly attached
observation surface. Sink failures retain the existing logical-failure rule.

### 8. Listener isolation is stated at the enforceable boundary

Motus isolates delivered data and swallows/counts listener exceptions. In 0.6
delivery is synchronous: a callback can delay the runner, and code that also
holds the Runtime can request cancellation. The contract no longer makes the
physically impossible claim that arbitrary in-process callbacks cannot affect
scheduling. Such influence must remain trace-visible.

## Compatibility

- Trace schema version remains 1.1.0; the wire shape does not change.
- GraphSpec schema version remains 1.0.0; only the already-declared R11 safety
  unit is corrected.
- The distribution becomes 0.6.1.
- No frozen Axis or Terraveler compatibility path changes.

## Verification gates

0.6.1 may be tagged only after:

- all stable adversarial tests pass;
- the complete pinned suite and frozen-path guard pass;
- JSON and JSONL validation agree for evidence-free rejections and bounded
  EXPLORATION cycles;
- keyed fact/decision lookup is sublinear and preserves exact origins;
- mutable callable configuration changes the next run's code fingerprint;
- supplied sinks are opened under every profile, and Listener cancellation is
  trace-visible under the documented synchronous boundary;
- a five-run corrected benchmark profile is committed from the reference
  GitHub runner and reproduced by CI;
- wheel isolation and zero runtime dependencies remain true;
- an independent re-audit returns no CRITICAL or HIGH finding.

## Consequences

The 0.7 branch remains closed until these gates pass. All deterministic
findings from the 0.6 audit are either corrected in code or, for Listener
scheduling, replaced by a narrower enforceable contract and regression test.
