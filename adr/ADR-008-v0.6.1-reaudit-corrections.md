# ADR-008 — Motus 0.6.1 independent re-audit corrections

- **Status:** ACCEPTED
- **Date:** 2026-08-05
- **Authority:** founder release gate requiring zero CRITICAL/HIGH findings
- **Accepted:** 2026-08-05 by the founder
- **Depends on:** ADR-007
- **Re-audit evidence:** PR #23 at `746b91b9f6da5c8020ea1da9bfb90265a3b557c9`

## Context

The independent re-audit confirmed all three original release blockers and
eight of nine original findings closed, but found one new HIGH defect and
three bounded defects.  Normal exhaustion of a `StreamDriver` did not mark the
driver closed, so context-manager exit issued a cancellation after the run had
already completed.  Because idle cancellation was allowed to queue forever,
that stale request silently cancelled the next run on a reused `Runtime`.

The same review found inconsistent failure handling for an explicitly attached
sink under `in-memory`, loss of the private rejection-absence singleton across
pickle, and unstated obligations on per-run `motus_config()` evaluation.

## Decision

### 1. Cancellation is bound, never inherited accidentally

`StreamDriver` becomes closed when its iterator terminates normally or raises;
context exit after termination is a no-op.  Closing an active driver retains
cooperative, trace-visible cancellation.

`Runtime.cancel()` returns whether it bound the request.  It cancels an active
run and may queue cancellation before the Runtime's first run.  Once a Runtime
has started at least once, an idle call returns `False` and cannot cancel a
later unrelated run.  Lifecycle inspection and mutation occur under one lock,
so a concurrent request either binds to the run or is reported as missed; it
never leaks forward.

### 2. A supplied sink is required; profile names crash durability

Supplying a `TraceSink` opts into a required observation surface under every
durability profile.  Both open and write failure therefore prevent logical
success.  `in-memory` still promises no survival after process loss; it does
not license silent loss while the process is alive.  Non-buffered attached
sinks receive records synchronously and the header records the effective
`flush_interval_ms: 0` and `chunk_records: 1` delivery configuration.

### 3. Absence survives supported Python isolation

The private rejection-absence sentinel reduces to its module singleton under
pickle in addition to shallow and deep copy.  A public `Rejection` that omits
evidence consequently omits it after ordinary cache, queue and multiprocessing
round trips.

### 4. `motus_config()` is an attestation method

A callable that opts into `motus_config()` MUST make it pure, total, cheap and
strict-JSON-valued.  Motus evaluates it at Runtime construction and each run
start so mutable configuration cannot produce stale identity.  A failure is
wrapped as `NodeConfigurationError`, a `MotusError`, before `run_started`; no
run trace exists because the runtime cannot truthfully construct its code
fingerprint.

## Compatibility

- Distribution remains 0.6.1.
- Trace schema remains 1.1.0; the optional `run.sink` object already permits
  the non-buffered disclosure.
- GraphSpec remains 1.0.0.
- Frozen Axis and Terraveler compatibility paths do not change.

## Release gate

ADR-008 may be accepted only after the four re-audit reproductions become
regression tests, the complete suite and frozen-path guard pass, the v0.6.1 SLO
gate remains green, and an independent re-audit reports no CRITICAL or HIGH.
