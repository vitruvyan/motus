THE PROPERTY (decided, not up for redesign): after a `seal()` that raised, the log is in exactly one of two states and says which — (a) RETRYABLE: nothing durable changed, memory is untouched, the window is still open, `begin()`/`end()` continue in it with the next sequence and no duplicate, a later `seal()` succeeds, and a reopen of the directory rebuilds the same chain; or (b) POISONED: something may have reached disk, so the instance refuses every later write. The line between them is the rename: a failure BEFORE `os.replace` returns is (a); a failure AT or AFTER it is (b).
