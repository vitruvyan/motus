# Motus 0.21.0 — Regulatory Evidence Dossier v1

Motus 0.21.0 adds the jurisdiction-neutral Regulatory Evidence Dossier v1
boundary accepted in ADR-042. One canonical manifest names a bounded set of
exact Motus artifacts while a separate deterministic ZIP preserves their
original bytes. Verification keeps dossier identity, semantic artifact
fingerprints, raw member digests and exact export identity distinct; it
composes existing Motus validators, supplied lineage and the included
Regulatory Evidence Profile without deciding completeness, legal sufficiency,
official submission, regulator acceptance or compliance.

## Verification and cost

Three independent Jenkins relative characterisations (`#29`, `#30`, `#31`)
against v0.20.0 measured canonical medians of **+1.6% / -0.8% / -3.5%**.
Their job ranges were **-5.1% to +5.7% / -4.5% to +0.3% / -5.0% to
+4.8%**. All pass the unchanged +10% per-release budget; every measured effect
is narrower than the worst paired spread.

The cumulative arm against v0.6.1 remains an explicit FAIL at
**+110.9% / +128.3% / +24.3%**, with ranges **+105.3% to +112.7% /
+123.0% to +148.3% / +23.0% to +27.8%**. ADR-018 leaves the anchor and
budget unchanged and permits release only with the fresh real-workload evidence
below.

Five live Orbis requests on `localhost:8001/run` produced contract-valid Motus
traces with integrity chains. Motus costs were **63.8 / 8.5 / 2.9 / 9.0 /
8.8 ms** against request durations of **10.341 / 15.964 / 6.664 / 7.621 /
12.284 s**. The conservative share, the worst cost over the fastest request,
is **0.957%**, below ADR-018's pre-registered 1% ceiling. The service still
omitted the health metadata expected by the probe, so the runs are honestly
classified `degraded`; this is Motus cost evidence, not Orbis health evidence.

Jenkins absolute-characterisation build `#32` used the same candidate SHA
`bf6be6acd9504c1e42639aafd52f53d8af82260e`. Its committed Python 3.10.12
profile identifies runtime `vitruvyan-motus/0.21.0` and passes the SLO baseline
gate, recording 224.255 microseconds per node and 16.896 milliseconds for the
100-node no-op subject. No figure is inherited from v0.20.0.

The release workflow appends the SHA-256 of the exact wheel and sdist below. Those
bytes will be stored as an immutable workflow artifact and as draft GitHub
Release assets. Publishing that draft would trigger PyPI and is not authorised.
