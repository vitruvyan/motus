# Motus 0.19.0 — Retention & Legal Hold v1

Motus 0.19.0 adds the jurisdiction-neutral Retention & Legal Hold v1 boundary
accepted in ADR-040. Immutable producer declarations, exact scope snapshots,
retention applications, trigger occurrences, and bounded custody observations
remain distinct evidence types. Read-only verification reports supplied lineage,
scope, binding, and blocker findings without selecting applicable law, inferring
legal authority or custody, or emitting disposal clearance.

## Verification and cost

Three independent Jenkins relative characterisations (`#21`, `#22`, `#23`)
against v0.18.0 measured canonical medians of **+2.7% / -2.0% / +0.1%**.
Their job ranges were **+1.5% to +5.7% / -12.6% to +3.4% / -1.7% to
+4.2%**. All pass the unchanged +10% per-release budget; every measured effect
is narrower than the worst paired spread.

The cumulative arm against v0.6.1 remains an explicit FAIL at
**+106.8% / +131.4% / +23.6%**, with ranges **+97.9% to +111.6% /
+130.2% to +149.8% / +22.8% to +28.9%**. ADR-018 leaves the anchor and
budget unchanged and permits release only with the fresh real-workload evidence
below.

Five live Orbis requests on `localhost:8001/run` produced contract-valid Motus
traces with integrity chains. Motus costs were **3.5 / 2.8 / 2.9 / 3.9 /
4.4 ms** against request durations of **11.515 / 21.364 / 7.848 / 26.030 /
17.690 s**. The conservative share, the worst cost over the fastest request,
is **0.056%**, below ADR-018's pre-registered 1% ceiling. The service still
omitted the health metadata expected by the probe, so the runs are honestly
classified `degraded`; this is Motus cost evidence, not Orbis health evidence.

Jenkins absolute-characterisation build `#24` used the same candidate SHA
`90787d4bfae1af7df17eea99ff31fcad461e2c72`. Its committed Python 3.10.12
profile identifies runtime `vitruvyan-motus/0.19.0` and passes the SLO baseline
gate, recording 230.218 microseconds per node and 17.523 milliseconds for the
100-node no-op subject. No figure is inherited from v0.18.0.

The release workflow appends the SHA-256 of the exact wheel and sdist below.
Those bytes are stored as an immutable workflow artifact and as draft GitHub
Release assets. Publishing that draft would trigger PyPI and is not authorised.
