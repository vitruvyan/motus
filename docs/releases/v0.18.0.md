# Motus 0.18.0 — Incident / CAPA Ledger v1

Motus 0.18.0 adds the jurisdiction-neutral Incident / CAPA Ledger v1 accepted
in ADR-039. Immutable `IncidentDeclaration` and `CAPAAction` revisions preserve
producer claims and link them to independently verifiable Motus evidence.
Deterministic ordering and binding verification expose missing evidence,
mismatches, supersession, and competing revisions without turning Motus into a
case-management or compliance engine. A valid incident or action does not prove
blame, reportability, root cause, effectiveness, adequacy, legal closure, or
regulatory compliance.

## Verification and cost

- Three independent Jenkins relative characterisations (`#13`, `#14`, `#15`)
  against v0.17.0 measured canonical medians of **-1.1% / +6.3% / +1.0%**.
  Their job ranges were **-2.7% to +1.6% / +1.1% to +8.4% / -5.5% to
  +3.2%**. All pass the unchanged +10% per-release budget, while the paired
  spread is wider than every measured effect.
- The cumulative arm against v0.6.1 remains an explicit FAIL at
  **+111.8% / +127.2% / +21.2%**, with ranges **+107.7% to +111.9% /
  +126.2% to +141.8% / +18.3% to +31.1%**. ADR-018 leaves the anchor and
  budget unchanged and permits release only with the fresh real-workload
  evidence below.
- Five live Orbis requests on the current `localhost:8001/run` binding produced
  contract-valid Motus traces with integrity chains. Motus costs were
  **3.1 / 3.0 / 5.5 / 2.7 / 2.5 ms** against request durations of
  **11.874 / 25.058 / 13.177 / 17.623 / 23.773 s**. The conservative share,
  the worst cost over the fastest request, is **0.046%**, below ADR-018's
  pre-registered 1% ceiling. The service still omitted the health metadata
  expected by the probe, so the runs are honestly classified `degraded`;
  this is Motus cost evidence, not Orbis health evidence.
- Jenkins absolute-characterisation build `#16` used the same candidate SHA;
  its committed profile passes the SLO baseline gate and identifies runtime
  `vitruvyan-motus/0.18.0`.

The release workflow appends the SHA-256 of the exact wheel and sdist below.
Those bytes are stored both as the immutable workflow artifact and as draft
GitHub Release assets. Publishing that draft would trigger PyPI and is not
authorised.
