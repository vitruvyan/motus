# Motus 0.23.0 — Third-party adapter profile and conformance kit v1

Motus 0.23.0 adds the contract-first, transport-neutral adapter boundary
accepted in ADR-044. Third-party adapters may translate transport and storage,
but Motus remains the semantic authority for validation, execution, evidence,
and result meaning.

The release ships a closed JSON Schema profile, a neutral conformance corpus,
an in-process reference adapter, deterministic conformance reporting, an
executable example, and an explicit Orbis mapping. Package bytes, typed result
fields, request identity, operation, scope, subject, and authoritative evidence
remain correlated across the boundary. Refusal, incomplete, and conflict
outcomes stay visible; adapters cannot silently reinterpret them as success.

## Verification and cost

Three independent Jenkins relative characterisations (`#37`, `#38`, `#39`)
against v0.22.0 measured canonical medians of **-3.2% / +4.7% / -2.4%**.
Their job ranges were **-3.7% to +2.4% / +4.2% to +8.2% / -3.9% to
+1.5%**. All pass the unchanged +10% per-release budget. The aggregate paired
spreads were 29.6%, 45.5%, and 30.8%, so the instrument does not resolve a
matching adapter-profile code effect.

The cumulative arm against v0.6.1 remains an explicit FAIL at
**+103.8% / +167.6% / +18.8%**, with ranges **+103.8% to +116.2% /
+140.8% to +183.7% / +18.2% to +19.8%**. ADR-018 leaves the anchor and
budget unchanged and permits release only with the fresh real-workload evidence
below.

Five live Orbis requests produced contract-valid Motus traces with integrity
chains. Motus costs were **13.0 / 9.9 / 15.0 / 3.1 / 7.4 ms** against request
durations of **21.137 / 23.481 / 8.104 / 16.939 / 15.874 s**. The
conservative share, the worst cost over the fastest request, is **0.185%**,
below ADR-018's pre-registered 1% ceiling. The service still omitted the health
metadata expected by the probe, so all five runs are honestly classified
`degraded`; this is Motus cost evidence, not Orbis health evidence.

Jenkins absolute-characterisation build `#40` used candidate SHA
`85b775f512b289222da10c500cc6461a7dc28399`. Its committed Python 3.10.12
profile identifies runtime `vitruvyan-motus/0.23.0` and passes the SLO baseline
gate, recording 206.670 microseconds per node and 16.016 milliseconds for the
100-node no-op subject. No figure is inherited from v0.22.0.

The release workflow will append the SHA-256 of the exact wheel and sdist. Those
bytes will be stored as an immutable workflow artifact and as draft GitHub
Release assets. Publishing that draft would trigger PyPI and is not authorised.
