# Motus 0.22.0 — Verification and Query API/CLI v1

Motus 0.22.0 adds the transport-neutral, read-only Verification and Query
API/CLI v1 boundary accepted in ADR-043. Callers explicitly type every supplied
artifact and request a closed inspection, verification, or projection over that
exact bounded collection. Motus composes its existing structural, binding,
lineage, package, dossier, and profile authorities without discovering external
evidence, guessing artifact kinds, selecting global current state, or issuing a
compliance or legal verdict.

The distinct `motus-evidence` CLI exposes deterministic JSON and terminal-safe
human output. Missing companions, duplicate identities, conflicting revisions,
forks, incomplete lineage, exhausted work budgets, and incomplete supplied-set
scope remain visible rather than being silently resolved.

## Verification and cost

Three independent Jenkins relative characterisations (`#33`, `#34`, `#35`)
against v0.21.0 measured canonical medians of **+3.5% / -6.7% / -2.1%**.
Their job ranges were **+1.6% to +7.3% / -9.7% to +7.7% / -11.5% to
-1.0%**. All pass the unchanged +10% per-release budget.

The cumulative arm against v0.6.1 remains an explicit FAIL at
**+112.3% / +129.9% / +16.4%**, with ranges **+103.3% to +120.8% /
+100.0% to +168.0% / +13.7% to +17.0%**. ADR-018 leaves the anchor and
budget unchanged and permits release only with the fresh real-workload evidence
below.

Five live Orbis requests on `localhost:8001/run` produced contract-valid Motus
traces with integrity chains. Motus costs were **6.5 / 14.6 / 3.2 / 3.4 /
2.5 ms** against request durations of **20.757 / 17.596 / 7.291 / 17.311 /
15.673 s**. The conservative share, the worst cost over the fastest request,
is **0.200%**, below ADR-018's pre-registered 1% ceiling. The largest observed
same-request share was **0.083%**. The service still omitted the health metadata
expected by the probe, so the runs are honestly classified `degraded`; this is
Motus cost evidence, not Orbis health evidence.

Jenkins absolute-characterisation build `#36` used the same candidate SHA
`77f326517919b68957d631588f8a79073eb91297`. Its committed Python 3.10.12
profile identifies runtime `vitruvyan-motus/0.22.0` and passes the SLO baseline
gate, recording 220.340 microseconds per node and 15.047 milliseconds for the
100-node no-op subject. No figure is inherited from v0.21.0.

The release workflow will append the SHA-256 of the exact wheel and sdist. Those
bytes will be stored as an immutable workflow artifact and as draft GitHub
Release assets. Publishing that draft would trigger PyPI and is not authorised.
